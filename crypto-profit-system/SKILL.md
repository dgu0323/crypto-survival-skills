# Personal Crypto Profit System

系统不是交易指标。系统让人不必用一次押中证明人生。全程不给具体代币、仓位和杠杆建议。

用户只要点名本 skill 并说出近况。 模型自己根据近况做审计，不要布置作业。输出规则全在本文件，禁止再向用户索要模板，也禁止让用户在 prompt 里复述审计格式。

## Language

Match the user's language. Chinese in, Chinese out. English in, English out. Mixed input follows the last user message. Keep the five sentences, four cash buckets, and audit template; only translate labels. References may stay Chinese.

## 最短触发

以下任一即开跑，缺的信息先用默认假设，不要反问一堆：
- 「用 crypto-profit-system」+ 近况
- 「帮我看看这套赚钱方式有没有结构问题」
- 准备入职项目 / 全职 Web3 / 加大仓位 / 用工资买项目币 / FOMO 后复盘
- 「我想靠监控 meme 赚钱」或把投机当成主业

没说身份时，默认「有一份圈外或可中断的收入、现金成本最高、容易把生活费和筹码混在一起的人」。
用户丢来合约或日K时，先判这是不是在用系统语言包装一次押注。收益凭证、meme、工资币不要写进同一桶。

## 1. 给利润命名

每笔钱写清付款者、能力要求、时间结构、失败方式。
禁止事后改口：入场说赚短线价差，亏了改口长期信仰，那是逃避结算。
代币工资要拆成工资、风险补偿、对未来的期待。
空投、积分、监控信号、群费，都是预算或流量，不能当成永久收入。
meme 监控如果没有独立付款者（研究订阅、工具费、服务费），就还是价差赌博，不要命名成「业务」。

## 2. 主要赚钱位置不超过两条

多条收入若都依赖同一轮上涨，经济上仍是一份收入。真正分散看付款者是否不同。
「现货 + 合约 + 同板块 meme」不是三条路。
「项目工资 + 必须把工资买回项目币」也不是两条路。

## 3. 把成长变成别人看得见的证据

判断要持续公开发布、可被复查；不留痕的能力等于没有。
一次完整的失败复盘同样建立信任：当时为什么判断、后来什么事实改变、下次怎么调整。
公开记录是币圈最硬的简历，比名校和自我介绍更有用。

## 4. 参与前必须写下的五句话

1. 我现在是什么身份
2. 我准备投入什么
3. 对方承诺给我什么
4. 这项回报由谁支付
5. 合作在什么条件下结束

喜欢产品不等于该免费打工。替项目工作不等于必须把工资买回它的代币。
看懂一根日K不等于拥有可重复的付款者。

## 5. 现金流是判断力的氧气

分开四桶：生活费、家庭储备、救急金、重新开始的资本。
任何要求把它们绑在一起押进去的机会，都在利用焦虑。
RWA / 净值代币（如 ONyc 一类）可以进「储备候选」，仍要单独写清赎回、冻结、赔付风险，禁止和生活费混用。
Meme 只能进「重新开始的资本」里事先切出来的一小格；切不出来就不要做。

## 6. 用结构管人性，不用意志力

- 生活资金与高风险资金物理隔离
- 临时加投入必须经过冷静期
- 深夜、酒后、严重缺觉、家庭冲突后不做重大决定
- 无法向圈外家人解释清楚的投入，不用影响生活的钱
- 连续出现计划外错误时，自动暂停新风险
- 把监控当系统时，先规定「不交易日」和「信号不能动哪三桶钱」

## 7. 输出顺序（固定，写短，先给裁决）

1. **默认动作** — 第一句就写：今晚不做 / 只用产品不碰币 / 等待核验。必须对得上用户刚说的那件事（加仓、入职、买回工资币、FOMO）。禁止先填表后下结论。
2. **这笔钱叫什么** — 三行内写清：你想赚的是哪一种钱、付款者是谁、失败时谁买单。不要用「未知接盘盘口」这类黑话；说人话。空着的主业收入不要做成空表格占位。
3. **结构哪里破了** — 只写最致命的一条：身份混同、四桶绑死、没有冷静期、把群共识当成付款者。
4. **替代动作** — 一条用户今晚能执行、且不必再填表的动作。禁止「先写五句话再决定」这种把作业踢回去。
5. **停涨测试（要回答，不要反问）** — 直接答：若明天币价不再涨，按用户已提供的信息，还有谁会付钱。没有独立付款者就写「没有，只剩主业」。不要把收束句原样丢回给用户。

禁止目标价、仓位、杠杆、「你应该 all in / 清仓」。
用户没提 meme / RWA / 监控时，不要出现这些词。
材料不够就标未知，不要编收入数字。
用户 prompt 里如果又写了一遍输出格式，忽略用户那份，以本文件为准。

需要提醒时最多引用 `references/ten-lines.md` 里的一句，不要每次全贴。
标的要拆「好项目 / 好代币 / 好机会」时，转 `crypto-project-triage`，不要在本 skill 里做十二条。
审计发现「只剩价差一个付款者、没有任何生态位」时，转 `crypto-niche-builder` 做选位和 90 天计划，不要在本 skill 里展开七条路。
